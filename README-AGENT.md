# Agent Operations Manual — Portfolio (2026 Refresh)

Purpose
- This is the source-of-truth playbook for any AI agent or engineer modifying this portfolio.
- It documents the current architecture, content ownership, visual system, personalization flow, build/deploy expectations, and safe transformation workflow.
- Use this file before making any non-trivial changes.

Scope
- Stack: React 19 + TanStack Router + Tailwind v4 + Framer Motion + TypeScript.
- Runtime model: single-page, anchor-scrolling experience rendered from the root route.
- Build target: static assets output to `docs/` for GitHub Pages.

---

## 1) Current Architecture (Must Understand First)

### 1.1 Rendering Model
- The app is now a single-page experience rendered by the root route.
- `src/routes/__root.tsx` renders:
  - `SiteNav`
  - `HomePage`
  - `SiteFooter`
  - fixed top scroll-progress bar via `useScrollProgress`
- Root route still owns meta tags and shell (`HeadContent`, `Scripts`, `QueryClientProvider`).

### 1.2 Route Behavior
- Canonical content route is effectively `/`.
- Legacy route files exist to preserve old URLs:
  - `src/routes/about.tsx` redirects to `/#about`
  - `src/routes/work.tsx` redirects to `/#work`
  - `src/routes/contact.tsx` redirects to `/#contact`
- These redirects currently use `window.location.replace(...)` in route loaders.

Important note
- `src/routes/work.tsx` and `src/routes/contact.tsx` still contain legacy component/content blocks below redirect setup. They are not used at runtime in the current flow, but still exist in code.
- Treat those blocks as legacy leftovers unless intentionally reactivating route-based pages.

### 1.3 Content Ownership
- Primary visible sections now live in `src/components/HomePage.tsx`:
  - `#hero`
  - `#about`
  - `#work`
  - `#contact`
- Navigation and footer interactions are in `src/components/SiteNav.tsx`.
- Hero atmospheric layers are in:
  - `src/components/HeroBackdrop.tsx`
  - `src/components/CodeRain.tsx`
- Scroll progress logic is in `src/hooks/useScrollProgress.ts`.

### 1.4 Router Setup
- `src/router.tsx` still initializes TanStack Router and query client context.
- File-based routes remain generated by `src/routeTree.gen.ts`.

## 2) Design System and Theme Rules

### 2.1 Active Theme Identity
- Theme name: Intelligent Systems Interface.
- Style: futuristic AI engineering portfolio.
- Intent: cinematic + technical + human-centered + premium.

### 2.2 Color Direction
- Primary dark background basis: near `#030303`.
- Accent basis: near `#123458`.
- Surface basis: near `#D4C9BE` influence for secondary tones.
- Primary text basis: near `#F1EFEC`.
- Palette is implemented through semantic tokens in `src/styles.css` using `oklch(...)` values.

### 2.3 Typography
- Current font imports in `src/styles.css`:
  - `Montserrat` (primary sans)
  - `JetBrains Mono`
  - `VT323`
  - `Press Start 2P`
- `--font-sans` is currently `Montserrat`.
- Keep terminal/engineering tone in mono labels and utility UI text.

### 2.4 Reusable Visual Utilities
Defined in `src/styles.css`:
- `.glass-card`
- `.elevate-hover`
- `.premium-button`
- `.ticker-mask`
- `.grid-paper`
- `.scanlines`
- `.noise`
- `.glow-gold`

Use these first before inventing ad-hoc visual effects.

### 2.5 Motion Rules
- Prefer subtle, premium easing and scroll-triggered reveal.
- Existing pattern in `HomePage.tsx`:
  - section variants with `hidden/visible`
  - `whileInView` reveal
- Avoid noisy motion, heavy parallax, or aggressive glow spam.

## 3) Personalization Source of Truth

### 3.1 Canonical Mapping File
- Use `MACHINE_MAPPING.json` as the canonical personalization data source.
- It contains:
  - global identity values
  - file replacement targets
  - post-action checklist

### 3.2 Priority Rule for Personalization
When values conflict:
1. `MACHINE_MAPPING.json` (highest)
2. Current runtime files (`HomePage.tsx`, `SiteNav.tsx`, root meta)
3. Any stale legacy route content in redirect files (lowest)

### 3.3 Current Personalization Touchpoints
- Meta/head: `src/routes/__root.tsx`
- Main content: `src/components/HomePage.tsx`
- Navigation/footer identity: `src/components/SiteNav.tsx`
- HTML title fallback: `index.html`
- GitHub Pages build settings: `vite.config.ts`

## 5) Transformation Workflow (Agent-Safe)

Use this sequence for every major redesign/personalization pass.

1. Rescan all ownership files before editing.
2. Verify runtime source files (especially `HomePage.tsx`) instead of assuming older route files are canonical.
3. Apply transformations atomically per file.
4. Keep component architecture intact (do not flatten everything into one file).
5. Do not add dependencies unless explicitly required.
6. Run `npm run build` and fix regressions.
7. Verify anchors and nav behavior manually:
   - `#hero`, `#about`, `#work`, `#contact`
8. Verify legacy URL redirects (`/about`, `/work`, `/contact`) still land correctly.
9. Confirm `docs/` output generated correctly.
10. Summarize changed files and rationale.

## 7) Common Pitfalls and Guardrails

1. Do not assume `src/routes/index.tsx` is active content source for the homepage. Current active source is `src/components/HomePage.tsx`.
2. Do not remove legacy redirect route files unless router structure is intentionally changed.
3. Do not break smooth anchor navigation expected by `SiteNav` and `SiteFooter`.
4. Do not change theme tokens casually; update semantic variables in `src/styles.css` instead.
5. Do not regress readability in favor of effects.
6. Keep mobile navigation behavior functional when redesigning nav.
7. Ensure CSS import order in `src/styles.css` keeps `@import url(...)` before other generated rule expansions to avoid warnings.
